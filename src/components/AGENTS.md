# Traffic component rules

- The Private Pilot oblique view always flies the full runway-13 left-hand VFR pattern, because only it lies in front of the fixed camera; live weather shapes climb, gust jitter and night dimming, never closes the pattern. Skip projected depths <150m and break guide paths across gaps to prevent behind-camera explosions.
- Journeys are scroll-driven (tail 0.5 stage after the last stage so a fling still shows it) (src/lib/journey-scroll.ts): native scrolling everywhere, crossfade = pure function of scrollY, each stage = var(--journey-stage) of scroll (100svh touch / 75vh desktop), JOURNEY_HOLD 0.72 of it holds the stage, the rest crossfades. The only assist is settleTarget: a rest position inside a crossfade is finished to the nearer edge (≤ half a window). Never add wheel/touch preventDefault, CSS scroll-snap, glides, paging, or anything that discards or delays input.

- Traffic tag sides are chosen once per display window with a look-ahead along the airplane path (fitTagSide in traffic-ui.tsx); no per-frame re-layout, positions snap to whole pixels, and a callout with no clear side is skipped, because per-frame flipping made tags jitter.
- Call placement uses the pure traffic-call-placement helper with screen-pixel leader caps and projected runway-relative side preference; panel collisions flip sides rather than extending leaders, keeping zoom independent of placement.
- Card placement is WeakMap-locked until out of bounds; stable contain-fit media prevents jumps. Shared desktop selection ignores aircraft pointerleave: close on actual pointer travel >24px away from opening point when over neither hit nor card, or panel exit; touch taps unchanged.
- TrafficPath derives lines and final extension from patternWaypoints used by the flight engine; labels are placed only after mount in constant screen pixels with live UI/card collision checks, so maps, aircraft and labels share geometry without hydration-dependent rendering.
- Both the airport-map drawn pattern and the Private Pilot oblique pattern line pulse with the shared usePatternPulse hook (traffic-path.tsx, site_settings.traffic_pattern_mode off/pulse/always): shown ~3 s every 6–8 s on maps and ~2.5 s every 15–20 s on the oblique view (OBLIQUE_PATTERN_PULSE), 600 ms CSS fade, paused while a card is open, never in reduced motion (owner request, 2026-11-04).
- Radio calls hold CALL_DURATION_MS (traffic-flight.ts); the calling plane is marked with .is-calling (pulsing target, full leader) and the SVG gets .has-call to dim other history trails, all in CSS so timing and placement code stay untouched.
- Sequencing is shared by both views: equal-period slots reserve final/runway/departure plus 5s. Real-speed rollout/climb, small arrival extension and departure-side upwind/downwind elongation absorb delay without recurring circles; validate spacing/order and <0.2 circles/lap. KLXL aerial has Apache/Phoenix/Cardinal. Groups carry legOf data-leg.
- Every airplane always shows a target ring (15px minimum, grows with the airplane in the oblique view) with a dark under-stroke, and [data-aircraft] carries a unit-relative dark drop-shadow, so tiny planes read on bright fields without changing scale or hit areas.
- GLB sources live in models-src/; public/models is packed from them with `gltfpack -cc -vpf -vt 12 -vn 8` and decoded by the self-hosted public/models/meshopt_decoder.js registered in aircraft-model.tsx. Never re-pack an already packed file (it collapsed geometry once); scripts/check-models.mjs guards this in build. Material polish (paint clearcoat, tinted BLEND glass, metal props, matte tyres) is applied to models-src copies by name before packing.
- Live-ops (live-traffic.ts, /api/public/live-traffic via adsb.lol, 8s cache, routeset origin/destination cached 10 min): airport maps keep the simulated pattern with a HUD readout; the Private Pilot oblique view switches to a live view (LIVE chip, dead-reckoned real aircraft, sim faded out) only when patternTraffic finds aircraft within 4 nm / 3,000 ft AGL. School tail numbers open their fleet card; others link to globe.adsb.lol by hex. ?livedemo (dev only) injects sample traffic.
- The oblique view draws N8570B/N4383P/N46201 from heading sprite atlases baked from models-src GLBs at the camera pitch (oblique-sprites.ts, 36 frames, frame = track minus line-of-sight bearing) at true literal scale (OBLIQUE_PLANE_BOOST = 1); other regs keep vectors. Target rings are sized per frame to 1.6x the on-screen span (ringRadius/setTagRing), min 11 px radius.
- Airport traffic always flies the pattern even in IFR (owner request); weather only shapes runway, wind, climb.
- Phone Story mode (site_settings.mobile_journey_mode, admin switch, read after mount so prerender stays scroll; dev ?story forces it) reuses FlightJourney: sections become one 100lvh screen, the viewport is touch-action none: horizontal drags follow the finger and commit on flick-direction or past halfway (Instagram-style), vertical drags follow the finger within one section boundary, then glide on release (flick or >30% pull) or settle back. Incoming native momentum is bounded too; only a fresh touch unlocks the next section, preventing one swipe from skipping sections. HUD shows the altitude climb; intentional forward taps on the last stage exit (story-nav.ts). Double-tap never zooms in (pinch only). Phone stories auto-advance every 5s while fully in view, hold while a finger is down, stop on the last stage. Computers use a looping Carousel (site_settings.desktop_journey_mode, separate admin switch, dev ?carousel): 5s per stage, pause/prev/next pill, arrow keys, trackpad sideways swipe; vertical scrolling stays native.
